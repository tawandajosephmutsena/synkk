# Contributing to Synkk

Thanks for helping make Synkk better. Users, testers, writers, designers, and developers are welcome.

## Choose a place to participate

- Use [Discussions](https://github.com/tawandajosephmutsena/synkk/discussions) for questions, ideas, feedback, and examples of how you use Synkk. Reply to others and use reactions to show interest.
- Use [Issues](https://github.com/tawandajosephmutsena/synkk/issues) for reproducible bugs and agreed, actionable work. Search existing issues before opening one.
- Use [Pull requests](https://github.com/tawandajosephmutsena/synkk/pulls) for code or documentation changes. Comment on and review open proposals if you can help.
- For Obsidian plugin changes, use the [plugin repository](https://github.com/tawandajosephmutsena/synk-obsidian-plugin). This repository contains the server and dashboard.

## Send a pull request

1. Open an issue or discussion first for a significant change so the approach can be discussed.
2. Fork the repository and create a focused branch. Clone with `--recurse-submodules` when your work includes the plugin checkout.
3. Follow the patterns in nearby files. Add or update tests for behavior changes, and run the relevant checks before submitting.
4. Explain the change, how you checked it, and any remaining limits in your pull request. Link the related issue or discussion.

Small fixes and documentation improvements can go straight to a pull request.

## Keep the space useful

Be respectful and specific. Critique ideas and code without attacking people. Avoid spam, harassment, and sharing someone else's private information. Maintainers may remove content that disrupts the conversation.

Never post credentials, device tokens, private vault content, or suspected vulnerability details in public issues, discussions, or pull requests. Follow the [private reporting guidance](README.md#security).
